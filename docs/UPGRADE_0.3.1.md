# Обновление с 0.3.0 до 0.3.1

Исправления: граничная дата фильтра возвращает ошибку проверки вместо OverflowError; folderId проверяется при сохранении (пусто или до 50 символов); при выходе очищаются формы и отбрасываются запоздавшие HTTP/JSON/XLSX-ответы, включая стартовый /api/me.

.env, роли, схема БД, Compose и OWUI не изменяются. Новых runtime-зависимостей нет. Исторический VALIDATION.json относится к 0.3.0; результат подготовки 0.3.1 — в VALIDATION_0.3.1.json. Полный HTTP/Docker-прогон пока не подтверждён.

## Перед применением

1. Сохраните исходники, .env и согласованную копию SQLite через backup API.
2. В старой панели проверьте, что сохранённый folderId пустой или не длиннее 50 символов; исправьте его до обновления, иначе новые строгие настройки не смогут прочитать некорректное старое значение.
3. Обновите исходники после обоих коммитов 0.3.1. Не заменяйте локальный offline Dockerfile, сети и override-файлы непроверенным архивом.
4. Соберите образ с прежними -p и -f. Прогоните весь Python-набор в одноразовом контейнере с каталогом tests; ожидается 43 теста. До подтверждённого OK не обновляйте рабочий контейнер.
5. Отдельный UI-тест: `node tests/test_panel_031.cjs` из корня репозитория. Для сервиса Node не нужен.
6. После успешных проверок пересоздайте сервис в обычном порядке и дождитесь healthy и версии 0.3.1 в /healthz. Проверьте вход обеими ролями, выход, фильтры и Excel в браузере. При откате проверяйте совместимость на копии.

Публикация коммитов сама по себе не меняет работающий контейнер.
