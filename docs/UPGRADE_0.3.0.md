# Обновление до 0.3.0

Добавлены форма входа, дополнительные учётки, серверное ограничение девяти полей подключения, LOGIN_SUCCESS и экспорт всех событий фильтра в XLSX. Новых Python-зависимостей нет.

## Порядок обновления

1. Сохраните .env, исходники и согласованную копию SQLite через backup API. Копии содержат сервисные данные и обслуживаются отдельно.
2. Обновите исходники, включая guard_admin.py, оба Dockerfile и Compose. Не заменяйте локальные сети/override-файлы без проверки.
3. Сохраните ADMIN_USER/ADMIN_PASSWORD и SEARCH_TOKEN. Дополнительные учётки задайте через GUARD_USERS_JSON как JSON-объект login:password в одинарных кавычках .env; пустой объект — без дополнительных учёток. Пароли всех учёток должны иметь 24..512 символов, включая администратора. Неверная длина останавливает запуск.
4. Для рабочего HTTPS оставьте SESSION_COOKIE_SECURE=true. Для локального входа по HTTP задайте false. SESSION_HOURS=8 — срок сеанса. Применение env требует пересоздания контейнера.
5. С теми же -p/-f соберите образ, выполните `python -m unittest discover -s tests -v` в одноразовом контейнере с подключённым каталогом tests. После OK запустите сервис с --force-recreate; дождитесь healthy и ответа /healthz версии 0.3.0.
6. Проверьте обе роли, AUTH и Excel. Под /search-guard/ сохраняйте завершающий /, Cookie/Set-Cookie и X-CSRF-Token. Внешний auth_basic proxy настраивается отдельно.

Миграция БД аддитивная: старые события сохраняются в пределах прежней ротации, получают тип SEARCH и пустой логин; добавляется таблица сеансов. Перед откатом проверяйте совместимость кода и БД на копии.

## Подтверждённая проверка

6 ноября 2026 пользователь предоставил вывод с рабочего хоста: 35 тестов за 0.372 секунды, OK; затем HTTP 200 /healthz с версией 0.3.0 и контейнер healthy. Тесты используют mocks и не доказывают качество классификации или доступность всех внешних сайтов. Результат отражён как предоставленный пользователем, не как независимый запуск CI.
