# Yandex Search Guard 0.3.1

Сервис проверки поисковых строк Open WebUI перед Yandex Search API: правила, локальный LLM-классификатор, многопользовательская панель и Excel-экспорт журнала.

0.3.1: исправлены обработка граничной даты журнала, проверка folderId при сохранении, очистка состояния панели и запоздавшие ответы прошлого сеанса. Полный HTTP/Docker-прогон новой версии пока не подтверждён. См. VALIDATION_0.3.1.json и docs/UPGRADE_0.3.1.md.

## Архитектура и работа

```text
OWUI (yandex) -> SEARCH_TOKEN -> Guard -> правила -> локальная LLM
                                               BLOCK/ошибка -> отказ
                                               ALLOW -> Yandex API
OWUI <- JSON с rawData <- Guard <--------------------+
Браузер -> HTTPS/reverse proxy -> форма входа -> панель
SQLite: настройки, журнал, сеансы
```

Проверяется query.queryText, не вся история чата автоматически. NFKC-нормализация и правила credentials, email, телефонов/номеров, непубличных IP, доменов и подстрок выполняются до LLM. Модель отвечает строго JSON с единственным decision=ALLOW/BLOCK и finish_reason=stop. При ошибке проверки поиск не выполняется. Перед отправкой payload пересобирается по allowlist; произвольные входные заголовки не передаются. searchType/region серверные, folderId необязателен и при заполнении ограничен 50 символами. rawData декодирует OWUI.

## Запуск и доступ

```bash
python3 init.py
docker compose -p yandex-search-guard up -d --build --wait
curl -fsS http://127.0.0.1:8091/healthz
```

init.py создаёт .env и не перезаписывает существующий. Основная учётка задаётся ADMIN_USER/ADMIN_PASSWORD. Дополнительные учётки — GUARD_USERS_JSON, JSON-объект login:password в одинарных кавычках .env. По умолчанию дополнительных учёток нет. Пароли всех учёток: 24..512 символов; логины: 1..64 символа A-Z/a-z/0-9/_.@-. Случайный пароль: `python3 -c "import secrets; print(secrets.token_urlsafe(32))"`. Реальные учётки не включаются в Git.

SESSION_HOURS=8 задаёт срок сеанса, допустимо 1..168 часов. Для рабочего HTTPS оставьте SESSION_COOKIE_SECURE=true. Для локального входа по HTTP явно задайте false. Форма входа заменяет Basic Auth приложения; внешний auth_basic reverse proxy управляется отдельно. После изменения env пересоздайте контейнер. Смена пароля/удаление учётки после применения конфигурации аннулирует её старые сеансы.

Порт по умолчанию 127.0.0.1:8091. Для сетевой панели используйте существующий HTTPS reverse proxy. Под /search-guard/ удаляйте префикс перед FastAPI, перенаправляйте путь без завершающего / на путь с /, пропускайте Cookie/Set-Cookie и X-CSRF-Token. Не кешируйте API.

## Роли и настройки

Только ADMIN_USER (обычно admin) изменяет llm_url, llm_model, llm_key, timeout, json_mode, yandex_key, folder_id, search_type, region. Проверка прав серверная; остальные учётки получают 403 при попытке записать эти поля. Правила, словари, политика, переключатели текстов, проверка строк, просмотр, экспорт и очистка доступны всем вошедшим. Очистка удаляет весь журнал независимо от фильтра.

API base модели вводится без /chat/completions; пример Ollama: http://ollama:11434/v1. Выберите локальный маршрут без внешнего fallback. При доступе через хост используйте опубликованный порт. Настоящий ключ Яндекса хранится в шлюзе; пустое поле ключа сохраняет прежний. Ключи не возвращаются admin API, но хранятся в SQLite без прикладного шифрования; .env, volume и backup обслуживаются как сервисные данные.

## Подключение OWUI

Обеспечьте связность контейнеров; примеры сетей — compose.network.yaml и фрагмент owui.compose.example.yaml.

```yaml
ENABLE_WEB_SEARCH: "True"
WEB_SEARCH_ENGINE: "yandex"
YANDEX_WEB_SEARCH_URL: "http://search-guard:8000/v2/web/search"
YANDEX_WEB_SEARCH_API_KEY: "<SEARCH_TOKEN>"
YANDEX_WEB_SEARCH_CONFIG: '{"query":{"searchType":"SEARCH_TYPE_RU"}}'
```

Сохранённые Admin Settings OWUI могут иметь приоритет над environment. SEARCH_TOKEN не является настоящим ключом Яндекса и не определяет пользователя OWUI.

## Журнал и Excel

Фильтры ALL/BLOCK/ALLOW/ERROR/AUTH, точный логин и даты UTC включительно. Панель показывает 200 событий, Excel — все сохранённые записи по фильтру. Время отображается в UTC. LOGIN_SUCCESS записывается при успешном входе, не при каждом API-запросе. Неуспешные входы не добавляются в журнал этой версии. Проверки из панели содержат логин; запросы OWUI с общим токеном — без логина.

Тексты ALLOW/BLOCK включаются независимо, по умолчанию выключены; сохраняется до 4096 символов без маскировки. ERROR/AUTH не содержат текста. Выключение флага не удаляет прежние записи. Очистка старше 30 дней — при старте, каждый час и при операциях журнала; дополнительно максимум 10 000 событий. При остановке очистка ждёт запуска. Backup ротируются отдельно; DELETE не является физическим стиранием или гарантией уменьшения файла. Журнал операционный, не полный неизменяемый аудит.

## Сборка, диагностика, тесты

Dockerfile использует pip-индекс; Dockerfile.offline — локальный wheelhouse без новых зависимостей для Excel. Для офлайн Compose задайте build.dockerfile: Dockerfile.offline; базовый образ и wheels Python 3.12 под архитектуру контейнера поставляются отдельно. Сохраняйте одинаковые -p/-f при всех командах.

```bash
docker compose -p yandex-search-guard run --rm --no-deps -v "$PWD/tests:/app/tests:ro" search-guard python -m unittest discover -s tests -v
```

Набор 0.3.1 содержит 43 Python-теста: 23 модульных/изолированных и 20 HTTP-тестов. В среде подготовки прошли 23 модульные проверки; HTTP-набор не запускался из-за отсутствия FastAPI. Отдельно прошли пять проверок панели с имитацией DOM и fetch: `node tests/test_panel_031.cjs` из корня репозитория. Node нужен только для этого теста, не для работы сервиса. Это не проверка в настоящем браузере. Подробности — VALIDATION_0.3.1.json. Исторический VALIDATION.json сохраняет предоставленный пользователем результат 35 тестов OK и healthy для 0.3.0, не для 0.3.1.

/healthz проверяет процесс; MODEL_ERROR — классификатор, YANDEX_ERROR — провайдер, BUSY — ожидание слота. Лимиты: 4096 символов, POST 64 KiB, 4 задачи, ожидание до 2 секунд, один worker.

Контролируется настроенный маршрут Yandex Search. Основная LLM, другие инструменты и чтение страниц настраиваются отдельно. Качество правил/модели проверяется на рабочих примерах, возможны пропуски и ложные блокировки.
