# Yandex Search Guard

Шлюз проверки поисковых запросов Open WebUI перед отправкой в Yandex Search API. Python/FastAPI, SQLite, Docker Compose, локальный OpenAI-compatible классификатор и административная веб-панель.

Это дополнительный контроль одного канала передачи данных, не сертифицированная DLP. Основная LLM, MCP/Tools, Terminal, загрузка найденных страниц и альтернативные поисковики находятся вне его защиты.

## Архитектура

```text
Open WebUI (engine=yandex)
  | POST /v2/web/search + SEARCH_TOKEN
  v
Search Guard
  |-- аутентификация и проверка структуры запроса
  |-- нормализация текста и детерминированные правила
  |-- локальная LLM -> BLOCK / ошибка -> отказ без поиска
  |                   ALLOW
  |                     v
  |-- пересборка разрешённых полей -> Yandex Search API
  |                                     |
  |<------------- JSON с rawData --------+
  |-- SQLite: настройки, ключи, журнал
  +-> ответ OWUI; выдачу декодирует OWUI

Администратор -> HTTPS/VPN/reverse proxy -> панель и admin API
```

## Принципы работы

Проверяется query.queryText, а не вся история чата автоматически. Нормализация NFKC и правила выполняются до LLM. Правила выявляют распространённые ключи/credentials, email, телефоны/длинные номера, непубличные IP, внутренние домены и запрещённые подстроки. Email/телефоны/IP переключаются; словари задаются без regex.

Модель получает строку как недоверенные данные. Разрешается только корректный JSON с единственным полем decision=ALLOW/BLOCK и finish_reason=stop. При ошибке/timeout/неполном ответе поиск запрещён; rules-only fallback нет. JSON mode не заменяет проверку ответа.

Перед внешним вызовом payload пересобирается по allowlist. Входные заголовки и произвольные метаданные не пересылаются. searchType/region берутся из серверных настроек. folderId необязателен; при заполнении используется серверное значение длиной до 50 символов. Неверное значение обнаруживается при подготовке внешнего запроса. Endpoint Яндекса фиксирован в коде.

ALLOW не гарантирует отсутствия чувствительных данных: правила и LLM могут ошибаться. Администратор считается доверенным и может менять политику и URL модели.

## Запуск и сборка

```bash
python3 init.py
docker compose -p yandex-search-guard up -d --build
curl -fsS http://127.0.0.1:8091/healthz
```

init.py создаёт .env и не перезаписывает существующий. Не публикуйте его. Панель доступна на http://127.0.0.1:8091. Для удалённой первичной настройки:

```bash
ssh -N -L 8091:127.0.0.1:8091 user@docker-host
```

Для постоянного доступа используйте HTTPS/VPN, сетевые ограничения и внешний rate limit. Встроенных SSO/RBAC и защиты от перебора нет.

Dockerfile устанавливает зависимости из доступного pip-индекса. Dockerfile.offline сохраняет вариант с локальным wheelhouse, без обращения pip к индексу. Для него нужны все совместимые Linux wheels под Python 3.12 и архитектуру контейнера:

```bash
docker build -f Dockerfile.offline -t yandex-search-guard:offline .
```

Чтобы Compose использовал этот вариант, задайте build.dockerfile: Dockerfile.offline в локальном override. Используйте тот же набор -f во всех командах. Базовый образ должен быть доступен отдельно; офлайн pip не делает загрузку образа офлайн. Wheelhouse и веса моделей в Git не входят. Pins верхнего уровня не фиксируют все транзитивные зависимости.

## Настройки модели и секреты

В панели задайте API base без /chat/completions, ID локальной instruction-модели, ключ при необходимости, timeout и JSON mode. Для Ollama в общей сети пример: http://ollama:11434/v1. При доступе через хост используйте его опубликованный порт, а не внутренний порт контейнера.

Проверьте, что backend действительно доверенный и не использует внешние fallback. Шлюз сам не доказывает локальность указанного endpoint.

ADMIN_PASSWORD используется только для панели; SEARCH_TOKEN — для OWUI. Настоящий API-ключ Яндекса хранится в шлюзе, не в OWUI. Сохранённые ключи не возвращаются admin API; пустое поле сохраняет прежний ключ. Настройки SQLite содержат ключи без прикладного шифрования. Защитите volume, Docker/root-доступ и backup.

## Подключение Open WebUI

Подключите OWUI и шлюз к общей Docker-сети и закрепите её в Compose, сохранив существующие сети. Сеть даёт связность, но не запрещает выход в интернет. Примеры: compose.network.yaml и owui.compose.example.yaml; последний не является самостоятельным OWUI stack.

```yaml
ENABLE_WEB_SEARCH: "True"
WEB_SEARCH_ENGINE: "yandex"
YANDEX_WEB_SEARCH_URL: "http://search-guard:8000/v2/web/search"
YANDEX_WEB_SEARCH_API_KEY: "<SEARCH_TOKEN>"
YANDEX_WEB_SEARCH_CONFIG: '{"query":{"searchType":"SEARCH_TYPE_RU"}}'
```

Сохранённые настройки OWUI могут иметь приоритет над environment: проверьте Admin Settings, не сбрасывая БД. Шлюз принимает Api-Key/Bearer с SEARCH_TOKEN, наружу использует настоящий ключ Яндекса.

Для панели под /search-guard/ фронтенд использует относительные URL. Reverse proxy должен удалять префикс, сохранять Authorization и перенаправлять /search-guard на /search-guard/. Не включайте кеш панели. Машинный поиск может обращаться к шлюзу напрямую по внутренней сети.

## Журнал v2

Метаданные: время, request_id, origin=test/yandex, решение, reason code, длительность. Панель показывает последние 200 подходящих событий, фильтры ALL/BLOCK/ALLOW/ERROR.

log_blocked_queries и log_allow_queries независимы и по умолчанию выключены. При включении сохраняется до 4096 символов исходного текста, не обязательно совпадающего с нормализованной строкой. ERROR не сохраняет текст. Выключение не удаляет ранее записанное.

Записи старше 30 дней удаляются при старте, каждый час, при записи/чтении журнала. Дополнительно действует предел 10 000 строк: история может быть короче 30 дней. При остановленном сервисе фоновая очистка не работает до запуска. DELETE не гарантирует уменьшение SQLite-файла или физическое стирание; VACUUM автоматически не выполняется. Backup ротируются отдельно. Лимит строк не является дисковой квотой.

Журнал не является неизменяемым аудитом: нет user ID OWUI, истории изменений политики; ранние HTTP-отказы могут не попадать в него. Ошибка записи после внешнего вызова не отменяет уже отправленный запрос.

## Диагностика и проверка

- /healthz подтверждает ответ процесса, не работоспособность LLM/Яндекса.
- MODEL_ALLOW с origin=test — проверка без Яндекса.
- FORWARDED с origin=yandex — успешный HTTP JSON-ответ с rawData, не гарантия полезности выдачи.
- MODEL_BLOCK — решение модели; MODEL_ERROR/MODEL_INCOMPLETE — технический отказ.
- EMAIL/CREDENTIAL/INTERNAL_DOMAIN и другие коды — срабатывания правил.
- YANDEX_ERROR — ошибка вызова провайдера, не семантический запрет.
- HTTP 401 — аутентификация; 403 — блокировка; 422 — payload/параметры; 503/BUSY — нагрузка.

Лимиты: 4096 символов запроса, 64 KiB POST, 4 задачи, ожидание слота до 2 секунд, один worker. Чтение найденных URL проверяется отдельно от поиска.

```bash
docker compose -p yandex-search-guard run --rm --no-deps   -v "$PWD/tests:/app/tests:ro" search-guard   python -m unittest discover -s tests -v
```

При дополнительных compose-файлах используйте тот же набор -f. Базовые mock-тесты и старый VALIDATION.json не подтверждают проверку всех новых патчей. Для экспорта с хоста проверены SHA-256, синтаксис Python и отдельные функции на временной SQLite: folderId, флаги текстов, 4096 символов, 30 дней и 10 000 строк. Полная FastAPI-интеграция, миграция, расписание lifespan, Docker build и live-вызовы в среде подготовки не запускались.

Перед эксплуатацией выполните регрессионные, нагрузочные и отказные испытания; проверьте обновления зависимостей. Обязательный контроль требует egress firewall, управления инструментами OWUI и правами, а не только Docker-сети.
